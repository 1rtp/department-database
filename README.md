# БД «Кафедра»

Курсовий проєкт з дисципліни «Бази даних»: проєктування та реалізація реляційної бази даних для інформаційного обслуговування керівного складу кафедри — облік викладачів, навчального навантаження, дисциплін та участі у науково-дослідних роботах (НДР).

---

## Технологічний стек

| Частина | Технології |
|---|---|
| **СУБД** | MySQL (InnoDB, utf8mb4) |
| **Логіка на рівні БД** | Збережені процедури, функції, тригери, views |
| **Проєктування** | ER-діаграма, UML Use Case, нормалізація 1НФ–3НФ |

---

## Структура проєкту

```
department-database/
└── department_database.sql   # Повний скрипт: схема, наповнення, процедури, функції, тригери, views
```

Один файл містить усе необхідне для розгортання бази з нуля.

---

## Швидкий старт

```bash
mysql -u root -p < department_database.sql
```

Скрипт сам створює базу `kafedra` (`DROP DATABASE IF EXISTS` + `CREATE DATABASE`), усі таблиці, наповнює їх тестовими даними та реєструє всю серверну логіку (процедури/функції/тригери/views).

---

## Схема бази даних

Спроєктована за результатами аналізу предметної області (ER-діаграма → реляційна модель → нормалізація до 3НФ).

| Таблиця | Призначення |
|---|---|
| `teacher` | Викладачі кафедри — ПІБ, посада, дата прийому, контакти, статус (звільнений/працює) |
| `subjects` | Навчальні дисципліни — назва, семестр, загальна кількість годин |
| `lesson_type` | Типи занять (лекція, практичне, лабораторне, семінар) |
| `assignment` | Призначення: зв'язує викладача, дисципліну й тип заняття, планові/вичитані години |
| `research` | Науково-дослідні роботи (НДР) — назва, дати початку й завершення |
| `participation_in_research` | Участь викладачів у НДР (зв'язуюча таблиця many-to-many) |

Усі зв'язки між таблицями реалізовані через `FOREIGN KEY` — цілісність даних контролюється на рівні СУБД.

## Серверна логіка

### Процедури (CRUD)

| Процедура | Призначення |
|---|---|
| `Adding_teacher` | Додавання викладача (з перевіркою дубліката за телефоном) |
| `Deleting_teaching` | "М'яке" видалення — зміна статусу на 0 замість фізичного видалення |
| `Adding_subject` / `Update_subject` / `Deleting_subject` | CRUD для дисциплін |
| `Adding_research` / `Update_research` / `Deleting_research` | CRUD для НДР (видалення каскадно чистить `participation_in_research`) |
| `Participation_check` | Перевірка участі конкретного викладача у конкретному проєкті |

### Функції

| Функція | Призначення |
|---|---|
| `Adding_assignment` / `Update_assignment` / `Deleting_assignment` | CRUD для призначень занять, повертають ID/кількість змінених рядків |
| `Total_Number_of_Scheduled_Hours_for_a_Teacher` | Сума планових годин викладача (`SUM`) |
| `Total_Number_of_Deducted_Hours_for_the_Teacher` | Сума фактично вичитаних годин викладача (`SUM`) |
| `Calculation_of_Remaining_Hours_for_a_Discipline` | Різниця між запланованими й вичитаними годинами дисципліни |

### Тригери (бізнес-правила)

| Тригер | Правило |
|---|---|
| `Prohibit_deletion_of_appointments_with_deducted_hours` | Забороняє видалити призначення, якщо години вже повністю вичитані |
| `Checking_Maximum_Load_of_a_Teacher` | Блокує нове призначення, якщо навантаження викладача перевищить 600 год/рік |
| `Automatic_Update_of_Project_Modification_Date` | Автоматично проставляє дату завершення при оновленні НДР |

### Аналітичні views (з агрегацією)

| View | Що показує |
|---|---|
| `Aggregate_Teacher_Load` | Зведене навантаження по кожному викладачу (`GROUP BY` + `SUM`) |
| `Research_with_number_of_participants_and_dates_of_conduction` | НДР з кількістю учасників (`GROUP BY` + `COUNT`) |
| `Disciplines_With_Remaining_Hours` | Дисципліни із залишковими (невичитаними) годинами |

## Приклади запитів

```sql
-- Загальне навантаження викладача
SELECT Total_Number_of_Scheduled_Hours_for_a_Teacher(3);

-- Зведене навантаження всіх викладачів
SELECT * FROM Aggregate_Teacher_Load;

-- Додати нового викладача
CALL Adding_teacher('Марія Шевцова', 'Асистент', '2018-02-05', '093 555-66-77', 'maria.sh@gmail.com');
```

## Нормалізація

Проєктування пройшло повний шлях від аналізу предметної області до фізичної моделі:

1. Побудова ER-діаграми (сутності: Викладачі, Дисципліни, Типи занять, Призначення занять, Наукові проєкти, Участь у НДР)
2. UML Use Case діаграма (актори: Викладач, Завідувач кафедри)
3. Приведення схеми до 1НФ → 2НФ → 3НФ з обґрунтуванням на кожному кроці
4. Фізична реалізація з `FOREIGN KEY`, `UNIQUE`, `NOT NULL` обмеженнями

## Поширені проблеми

| Проблема | Причина | Рішення |
|---|---|---|
| `ERROR 1046 (3D000): No database selected` | Запуск без імпорту всього файлу | Виконуйте весь скрипт одразу: `mysql -u root -p < department_database.sql` |
| Тригер `Checking_Maximum_Load_of_a_Teacher` блокує вставку | Навантаження викладача вже близько 600 год/рік | Це очікувана поведінка — бізнес-правило, а не помилка |
| Помилка при `DELIMITER //` у GUI-клієнтах | Деякі клієнти (phpMyAdmin) не підтримують `DELIMITER` у звичайному SQL-вікні | Імпортуйте файл цілком через "Import", а не через SQL-редактор рядок за рядком |
